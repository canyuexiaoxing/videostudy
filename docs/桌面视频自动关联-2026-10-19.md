# 桌面视频自动关联（0.1.9）

用户要求以桌面软件为准，不再通过手动确认关联视频。此次不修改课程分析、同页分组、导图生成或模型调用逻辑。

## 行为

- 上传后，后端直接从收到的原文件计算并保存大小及指纹，后续清理上传文件不会删除这两项数据。使用与原前端一致的算法：文件大小的 8 字节大端编码、开头 64 KiB 和末尾 64 KiB，计算 SHA-256；短文件的重叠部分仍按原算法计算。
- 前端只接受服务端返回的指纹作为课程关联依据，原 localStorage 指纹及 user_confirmed 标记均不能授予关联。保留旧缓存中的名称仅用于历史名称展示。
- 软件通过隔离预加载桥取得用户选中文件的实际位置，在软件用户数据目录 media-library.json 中记住指纹与路径；路径不上传到后端。
- 读取历史时，保留已匹配的视频和播放位置；否则从记住的路径重新计算指纹，匹配后自动恢复本地视频。文件改名、移动或删除后，原路径失效时提示重新选择，再自动核对。
- 原文件播放使用只在本次软件运行中有效的随机令牌地址，支持流式读取、字节范围及 HEAD，不需要为恢复播放将整个视频读入内存。
- 手动确认与解除手动关联按钮已删除。旧的手动确认数据不再生效。
- 已匹配课程的字幕、导图、练习及课件跳转继续使用统一的实际播放器跳转校验；本地笔记仍可独立回看。
- 历史分析不依赖指纹查询成功：指纹服务不可用或原文件缺失时仍能查看历史内容，但不授予课程播放关联。

## 旧记录

GET /api/transcriptions/{id}/media 优先读取已保存的指纹。对于缺少指纹的旧任务，仅从仍留在上传目录的原文件补算；已清理则返回 410，不能凭文件名或用户确认建立关联。

部署检查现有 12 条历史：全部上传原文件已清理，可补算 0 条。没有擅自用本地同名视频绑定，也没有重新分析课程或调用收费模型。这批旧记录仍能查看分析，但暂时无法自动关联；此限制不能通过此次新增数据库字段消除。

## 验证

- 前端和桌面单元测试：93 项。
- 后端回归：包括跨端算法一致性、旧文件补算、原文件缺失、数据库持久化与清理后读取。
- 实际 0.1.9 软件：独立用户目录，模拟历史 API；选择原视频自动关联，关闭后重新启动，打开历史无需再选文件即可恢复视频；实际点击字幕及导图，检查 video.currentTime；Range 请求返回 206 和准确字节数；文件删除不自动绑定；原上传文件已清理仍能加载历史。
- 证据：.local/qa/native-media/verification-packaged.json、deployment.json，.local/qa/media-identity-maven.log。
- 辅助脚本：scripts/dev/qa/native-media.mjs；部署 scripts/dev/deploy/desktop-media.py 先检查无活动任务，仅更新 Java API，不重启模型服务。

## 交付

最新软件路径以 .local/releases/latest.json 为准。退出旧软件后运行新的 Framewise.exe。笔记和预览缓存仍是原来的本机数据，本次没有进行跨设备同步。

## 0.1.10 后续调整

已增加本地自动指纹优先读取、后端补缓存和旧缓存自动迁移，不再仅依赖后端。旧缓存能否恢复关联取决于对应历史记录仍在，以及原客户端是否仍有自动保存的指纹。详见《本地指纹优先与课程对话-2026-10-19.md》。
