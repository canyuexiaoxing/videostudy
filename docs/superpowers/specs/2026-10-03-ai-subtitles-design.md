# 中英 AI 字幕设计

## 目标与已确认约束

在现有 VideoStudy 分析流程中保留 Whisper 原始转写，增加中文、英文的校准/翻译字幕。用户可以随时切换原始与 AI 版本，视频播放位置不变。该功能由用户在 2026-10-03 明确要求开始实现，沿用此前已讨论的方案，不增加人工核对环节。

- 同语言校准遵循近音纠错，保留原意、口语结构和起止时间，不根据常识替老师改正知识错误。
- 原则上不增删正文；不得以净长度相同掩盖大量增删。中文每条字幕最多实际插入/删除一个正文字符，英文最多一个单词；这是对每句上限的保守实现。
- 多余语气词、英文填充词不得凭空加入；标点、空格不计正文长度。缺少证据时保留原文。
- 中英互译不限制近音和增删字数，要求忠实、简明，沿用原始 ID、时间和字幕顺序。
- 文本模型只读取转写、附近讲解、同页 OCR 和来源时间，没有听原音或看图片，不宣称声学校验。
- 默认自动生成原语言校准版；高级选项可关闭或选择目标中文/英文。

## 数据流与后台执行

语音转写、OCR、覆盖检查和同页分组完成后，Python 异步将来源文字传给 Java 独立字幕任务。页面理解与导图照常继续。主分析成功、失败和媒体清理不等待字幕处理；字幕失败不改变主任务状态。

Java 每个课程生成一个私有随机回调令牌，由分析请求传给 Python。Python 在同页分组后，向固定内部 Java 地址发送包含令牌的来源事件，最多三次自动传输重试。事件持久化后独立 Worker 调用 Python `/subtitles`。当事件传输失败，主分析完成结果提供来源回退，保证字幕最终可生成；这个回退可能晚于导图，但正常路径在分组后启动。

持久化字幕来源和每种目标语言的任务/结果，与转写记录关联并级联删除；完成写入检查任务仍存在，删除不能被晚到结果撤销。后台状态由数据库驱动，支持有界队列、幂等提交和服务重启恢复。来源只有文字，不依赖已删除的临时视频或图片文件。

## 接口

同语言校准先执行时间/引用/近音/增删规则校验，再集中复核通过规则的候选修改及其附近上下文。复核只能认可或舍弃已有修改，不得写入新的改写。读音接近但仍不成词、缺少依据或语义不成立的修改保留原文。复核网络/格式错误最多尝试三次，失败时保留原文并标记部分完成；不进入循环，也不重新处理音视频。翻译不走近音校准复核，仍保留原始时间和回退规则。

- 上传增加 `aiSubtitles=true|false` 和 `subtitleTargetLanguage=source|zh|en`。
- `GET /api/transcriptions/{id}/subtitles?targetLanguage=source|zh|en` 返回独立状态、结果和错误。
- `POST /api/transcriptions/{id}/subtitles` 请求已有课程或另一目标语言的字幕。已有运行或成功任务不重复提交。
- 内部 `POST /api/internal/transcriptions/{id}/subtitle-source`，验证 `X-Subtitle-Token`，只接受该课程的文字来源。
- Python `POST /subtitles` 输入语言、原始片段、页面组、目标语言，输出完整字幕、已接受修改、理由、OCR 依据、被拒绝数量、处理状态、调用统计。

## 前端

原始转写始终保留，不影响知识图依据、时间跳转和笔记。播放器字幕开关独立于原始/AI 模式选择。校准待处理或失败时使用原始字幕并显示状态；已有课程可直接基于保存文字生成。原生 WebVTT 字幕支持全屏；切换仅替换字幕轨道，不更换视频地址。转写面板提供修改对照和依据时间。

## 验证与风险

验证近音替换、错误改写拒绝、真实增删计数、跨语言时间保留、非法 ID 与伪造 OCR 依据拒绝、API 有界重试、部分失败回退。验证来源事件先于页面理解/导图、字幕任务不阻塞主流程、关闭选项、重启、删除竞争和旧任务生成。验证浏览器字幕切换、播放位置和全屏轨道。

准确率需要独立原音参考字幕评测，不能以输出变通顺或模型自报信心证明。拼音/英文音码约束是保守过滤，不是声学匹配保证。后台并行会增加 API 请求和费用，可能受限流影响，记录调用量及耗时。图像识别、Whisper 模型和既有粗选规则不在本次修改范围。
