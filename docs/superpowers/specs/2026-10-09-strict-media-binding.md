# 视频与历史解析的严格关联

用户确认：只有确认指纹匹配才关联回放，未知不能默认放行；换视频时立即切断旧关联，所有工作台功能一起切换，迟到的旧响应不能重新填入资料。

## 实现

统一 `mediaBindingState` 规则：有效的 64 位十六进制 SHA-256 抽样指纹与文件大小都一致才匹配。缺少、损坏、格式无效的记录均为“无法确认”。文件名不作为身份依据，原文件改名不影响匹配。指纹算法维持文件大小加头尾各 64 KB 的抽样哈希，没有改为全文件哈希。

选择视频时立即让旧上传/轮询/导图生成失效，清空当前解析编号、字幕、导图、页面、章节等资料和旧播放关联。计算完指纹后，只有匹配才恢复刚才的正确历史上下文；其他情况进入新视频待分析状态，历史数据库记录和本地历史列表不删除。此时练习显示待分析提示，不展示旧题或固定演示题。

先选视频再读历史，同样核对指纹：无法确认或不匹配则解除视频关联，历史资料仍可浏览。字幕轨道、时间章节及课程依据回放仅使用已确认的视频身份；导图、练习、解读、课件的回看入口统一走受保护的播放器入口。

异步请求使用可失效的请求标记和 AbortController；读取响应后再核对标记，旧请求的成功、失败、结束回调都不能覆盖新上下文。新文件指纹读取也有最新请求保护。取消客户端请求不会承诺已经开始的后台分析被取消。

## 验证

- `mediaBinding.test.mjs`：缺少/损坏/无效指纹不能匹配；大小和指纹都须一致；原文件改名可匹配；新上下文中旧请求失效。
- 隔离浏览器通过真实文件选择事件验证：缺少指纹拒绝关联、匹配原文件、改名原文件、换成不同文件清空旧材料与题目/字幕轨道；强制让忽略取消的旧响应迟到，仍不会覆盖新文件；无指纹历史资料可读但视频被解除关联。没有调用出题模型。
- Vue 类型检查、正式构建通过。

此规则防止错误关联，不声称抽样指纹等同于全文件一致性证明。旧记录如果缺少有效指纹，需重新分析原视频建立新记录后才能确认关联回放。
