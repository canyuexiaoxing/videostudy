# 按组并行分析与整课导图实施计划

目标：以同页截图集合为组。四组代表图+对应语音就绪后启动，最多五组并行；之后逐组提交，尾部不足四组在分组结束后提交。保留页面解析且共同产出知识/例题候选，最后一次图文整课汇总。模糊/解析失败图直接可送全课Agent，不猜内容。

## 实施与接口
1. 媒体回调：transcribe_file(on_segment)、VisualOcrWorker.analyze(on_frame)、IncrementalPageGrouper(add/finish)。闭合组_closedAtMs确定语音窗口。原接口保持兼容。
2. ReadyGroupScheduler：完整组输入、当前语音watermark和截图组成版本；前后组预览影响contextRevision。等待四组仅发生首次；修订及迟到回复受版本保护。补图最多两次，衔接补做上限两次，取消停止新请求并拒绝迟到。
3. analyze_group：当前HD/OCR/语音+就绪邻组低清预览和边界语音；独立内容、知识延续、例题延续、回顾、不确定引用校验；需要邻组HD时有界补充。同主题不自动当同例题。
4. course_mind_map：统一看全课候选、衔接证据、不确定项，必要原图作为直接证据。程序验证speech/image引用，计算节点时间。一个概念/方法一节点，细节分离；例题单入口，不靠主题相同合题。
5. Java/frontend：groupedAnalysis显式选择并持久化，默认不自动切换旧流程。details/image引用和groupUnderstanding透传、来源验证、图片回看、练习范围、服务端取消及重试，动态组进度。

## 验证要求
所有provider注入模拟reply，不调用收费模型，不自动重新分析历史课程；模拟增量就绪、不足四组、五并发、晚邻组补衔接、分组改变、补图预算、取消/迟到、失败重试、跨页同题/不同题、未念公式、模糊图转发和非法引用。再用已有真实截图/转写离线验证Java/前端显示。收费模式需界面显式选择。旧数据保留兼容，完工更新交接。
