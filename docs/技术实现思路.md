# VideoStudy 技术实现思路（首版）

> 状态：实现方案草案，供团队拆任务使用；不代表代码已完成。
>
> 对应文档：[需求分析](./需求分析.md)、[系统设计方案](./系统设计方案.md)。
>
> 范围：课程分析 → 带出处的知识图 → 学生回答 → 错因诊断 → 视频回看 → 针对性追问。截图反查、导入原 PPT、自动传播纠错、跨课程整合暂不进入首版。

## 1. 总体选择

首版按 **桌面软件 + 服务器分析** 实现：用户电脑只安装 Electron + Vue；Java Spring Boot + MySQL、Python Agent、FFmpeg、转写/OCR 运行在服务器；文本推理由 Python 调用 DeepSeek API。Electron 选择并播放本地原视频，分析时通过 HTTPS 临时上传完整视频。Java 负责业务 API、上传、任务和数据；Python 负责媒体分析与 AI；处理结果入 MySQL 后，服务器删除临时视频和中间文件。用户之后点击节点，仍由 Electron 播放本地原视频。

服务器以 MySQL 任务表 + Java 调度器 + 有界 Python Worker 排队，首版不部署 RabbitMQ。MySQL 只装在服务器。若后期需要减少上传流量，再探索客户端提取音频与候选 PPT 截图；这会增加客户端 FFmpeg 打包和兼容工作，不纳入首版。

建议目录：

~~~text
videostudy/
├─ frontend/             # Vue 页面、播放器、导图、答题与诊断交互
├─ desktop/              # Electron 主进程、文件选择、本地文件关联与上传
├─ backend-java/         # Spring Boot API、上传、任务、MySQL 持久化
├─ agent-python/         # 服务器端转写、OCR、知识抽取、诊断与检索
├─ schemas/              # Java/Python 共用的 JSON Schema 与样例
├─ eval/                 # 人工标注样本、评测脚本、结果说明
└─ docs/                 # 需求、设计、运行说明、资源清单
~~~

ASR/OCR 模型版本与许可证、DeepSeek API 模型 ID/费用/条款及服务器设备要求先做小样本试验，再写入正式依赖清单；不提前承诺某模型的质量或速度。
## 2. 先做一条最小纵向流程

不要一开始就接一小时视频和全套 OCR。按这个顺序打通：

1. **十分钟以内的授权课程样本**：Vue 选择本地视频，播放器能 seek；Java 建立课程记录。
2. **转写结果进入系统**：Python 返回带毫秒时间段的片段；Vue 点一句转写即可跳转播放。
3. **手工标注少量概念关系与错因样例**：先用人工整理的 5～10 个知识关系、两类错误回答跑通诊断链，排除接口和产品逻辑问题。
4. **自动知识抽取与证据校验**：模型从转写片段产生概念和关系，但只能引用输入中的片段 ID；Java 验证 ID、时间与原文存在。
5. **学生答题闭环**：同一道题给出两种不同错误回答，系统展示不同错因、不同推荐片段与不同追问；新回答改变掌握状态。
6. **接入 PPT 粗选与 OCR**：先验证它是否补上语音没有说出的关键信息。若效果不稳定，保留纯音频主线，OCR 作为可关闭的增强。
7. **扩大到一小时样本**：测试分段处理、内存、缓存、失败恢复和总耗时。

这样即使视觉处理尚未成熟，参赛核心流程仍可运行。

## 3. 客户端、上传与服务器任务

### 3.1 桌面客户端

Electron 打开 Vue 窗口和文件选择器，保存课程 ID 与本地文件的关联；播放器直接读本地原视频。Electron 不启动 Java、Python、FFmpeg 或模型。客户端对外只调用 Java HTTPS API。重新打开软件时若本地视频仍在，可继续跳转；若文件移动、删除或换设备，要求重新选择并核验文件指纹。服务器不保存用户电脑上的绝对路径。

### 3.2 临时上传与删除

首版把完整视频分片上传到服务器。Java 创建上传会话，校验登录用户、格式、声明大小和空间配额；支持断点续传、取消与重复分片校验。服务器仅在受控临时目录合并文件，并将该文件关联到分析任务。Python 在服务器读取它，不依赖用户电脑路径。上传时间和临时磁盘占用须在一小时样本上实测。

分析完成且结果成功入 MySQL 后，删除服务器视频、提取音频和不再需要的截图。失败、取消或断线留下的文件由定时清理任务在规定期限内清理；删除失败需记录并重试。长期保存的是转写、OCR 文字、知识关系、证据时间及必要的缩略信息，不长期保存原视频。删除服务器副本不会影响已选定的本地原文件播放。

### 3.3 分析任务与并发

Java 在 MySQL 创建任务，状态依次为 uploading / queued / extracting / transcribing / sampling / ocr / aligning / graphing / validating / completed；失败为 failed，取消为 cancelled。Java 调度器按受限并发从 MySQL 领取任务、记录租约与心跳，再通过内部 HTTP 派发给 Python Worker，避免单张显卡同时运行多个重任务。Java 为任务设置最大重试次数、排队上限及超时；软件轮询任务进度。重新启动服务时，依据 MySQL 任务记录恢复可重试任务。

Java 与 Python 只传 jobId、受控临时文件引用和配置，不把视频放进任务消息。首版固定由 Java 调度器调用 Python Worker 的内部 HTTP 接口，Python 不直连 MySQL；两者同机部署或共享受控临时目录，并用契约测试锁定接口。多服务器规模化后再引入 RabbitMQ。
## 4. 课程内容处理

### 4.1 语音转写

Python 用 FFmpeg 提取单声道音轨，再调用选定的多语言 ASR。长音频按模型能力分段处理，输出：

```json
{
  "segmentId": "t_001",
  "startMs": 152000,
  "endMs": 158400,
  "text": "训练集表现很好，但测试集表现明显变差",
  "source": "asr"
}
```

时间一律用媒体起点后的毫秒，不能把分段音频内的局部时间误当作视频全局时间。模型可能出现漏词、错词、静音幻觉，保存原始转写及经校正文本的对应关系；没有依据时不把大模型润色内容当作老师原话。

### 4.2 PPT 候选画面

如果输入是视频，FFmpeg 每约 2 秒采样一帧做**轻量比较**，不先把约 1800 张一小时采样图全部送 OCR。可先统一缩小、裁去黑边，再计算颜色直方图或感知哈希差异；对变化候选进行局部像素差异核验。程序把连续变化归为一个“页面变化簇”，在变化稳定后保留一张或少数几张代表画面。

PPT 动画可能逐项出现，所以同时保留“页面开始时间”和“当前最充分内容的画面时间”。若 08 秒画面有内容、10 秒已翻页，回查 08～10 秒，以 0.5 秒间隔补采，并优先选翻页前最后一张清晰、非过渡的画面。这里无法证明画面“绝对完整”，只能在有限预算内选最充分的可见状态。对板书、频繁切镜头或录屏弹窗，可先关闭视觉增强或降低自动判断置信度。

### 4.3 OCR 与时间对齐

仅对候选代表帧 OCR。每个 OCR 块保存文本、截图时间、图片坐标和置信度。按照 PPT 版面坐标聚类为标题、正文、图注等候选区域，但不假定所有页面都按文章顺序排列。文本模型接收的是结构化 OCR 文本、版面位置和对应时间，不声称它直接看懂图片。

把某张 PPT 的生效时间段与同段语音转写对齐。语音优先表达老师实际讲解内容；OCR 用于补充画面里没有说出的文字。若冲突，分别标记来源，避免合成一个未经证实的陈述。只有当视觉信息确实改善知识图或定位时，才保留 OCR 为首版默认流程。

### 4.4 带出处的知识图

转写及 OCR 先分段、去重，再调用 DeepSeek API 生成候选概念和关系。例如：

```json
{
  "relationId": "r_017",
  "from": "训练集表现",
  "type": "contrasts_with",
  "to": "测试集表现",
  "claim": "过拟合时训练表现可能很好而测试表现下降",
  "evidenceRefs": ["t_001", "t_002"],
  "status": "candidate"
}
```

程序先做**硬校验**：引用 ID 必须存在、时间不越界、引用原句可查。随后再做**语义校验**：被引用内容是否支持这句话；没有充分支持的关系不直接显示为已确认知识。抽取结果可按 `candidate / supported / rejected` 状态保存，记录模型与提示词版本。对于“因果关系”要求比普通“同段提及”更强的证据。

前端把知识图显示为导图或关系图；点击节点和连线都能展示依据并跳到视频。导图布局是视图，知识关系与证据才是底层数据。

## 5. 错因诊断 Agent

### 5.1 错因集合与教师样本

先由团队和熟悉课程的人给目标知识点定义有限错因类型，例如：概念记忆错误、混淆两个概念、因果推理缺步、适用条件误用、信息不足。每个错因至少有描述、可识别的回答迹象、对应的正确知识关系、适合回看的课程片段。不要让模型为每个回答临时发明一个无法评测的新标签。

教师或助教预先标注一批不同回答，包括正确、两种以上错因、模糊、部分正确和超出课程范围。标注数据用于评测，不把标准答案整段暴露给被测模型。

### 5.2 诊断流程

1. Java 接收题目 ID 和学生回答，检索题目涉及的概念、评价要点及证据候选。
2. Python 调用 DeepSeek API 输出结构化候选：错因类别、学生回答中的原话跨度、缺失或错误的概念关系、判断理由。
3. 校验器确认原话跨度确实在学生回答中，相关概念和关系存在；置信不足或多个错因无法区分时，返回 `needs_clarification` 和一个区分性追问。
4. 按**错因**查询相关课程关系和片段，重排时考虑片段是否真正解释这个缺口、是否包含足够上下文、长度是否适合回看。不能只按题目关键词搜索。
5. 输出包含错因、学生原话、原课引用、推荐起止时间和追问目的。Java 再验证所有引用和区间后保存。
6. 学生点击回看，Vue 对原视频设置 `currentTime` 并播放。观看完成不等于掌握，必须回答新情境追问。
7. 再诊断新回答，更新为 `待验证 / 初步掌握 / 仍需学习` 等状态；保存整个交互链。

诊断结构示例：

```json
{
  "attemptId": "a_042",
  "status": "supported",
  "errorType": "concept_confusion",
  "answerQuote": "训练集准确率低就是过拟合",
  "explanation": "把训练集表现与测试集表现混为一谈",
  "evidenceRefs": ["t_001", "t_002"],
  "remedy": {"startMs": 149000, "endMs": 185000},
  "followUp": {
    "question": "若训练集准确率很高而测试集明显下降，可能发生了什么？",
    "targetRelationId": "r_017"
  }
}
```

这只是契约样例，不能作为真实系统测试结果。

### 5.3 Agent 工具与预算

Agent 可调用的工具只包括：按时间取转写片段、检索知识关系、读取候选 OCR、按指定局部时间范围补采画面、复核引用。每类工具设置最大调用次数、时间范围和超时；不能执行任意 shell 或遍历用户磁盘。课程正文和 OCR 是待分析数据，不是系统指令。

## 6. 接口与持久化

前端只访问 Java API。关键接口：导入媒体、启动/查询分析任务、读取转写、读取知识图、提交回答、获取诊断、提交追问答案、读取学习记录。长任务返回任务 ID，前端轮询；短诊断请求可同步返回，但应有超时与任务化回退。所有接口给出稳定错误码，避免只返回一段模型自然语言。

Java 在服务器使用 MySQL 保存用户、课程、上传会话、任务、转写、图节点、关系、引用、练习、回答和诊断；通过 Spring Data JPA 或 MyBatis 访问，表结构变更用 Flyway 管理。大视频、临时截图和模型权重不放数据库。Java/Python 共用 JSON Schema 样例作为接口契约；DeepSeek API 的 JSON 响应由 Python 解析并再次校验，时间单位统一毫秒，引用使用稳定 ID。MySQL 凭据只保存在服务器配置中，不写入仓库；客户端不直连 MySQL。

## 7. 实际验证与参赛证据

调用 DeepSeek 前由服务器检索并截取必要的转写/OCR 片段与学生回答；不把完整视频发送给 DeepSeek。记录请求次数、token 用量、延迟和失败重试。用户需了解转写、OCR 文字和学生回答会交由第三方模型处理；API Key 不进入桌面端和公开仓库。

**功能验证**：使用授权的短视频走完全流程；同一道题输入不同错误回答，分别展示不同错因、视频片段与追问。测试本地媒体移动、无音轨、OCR 为空、分析取消和失败重试。

**效果验证**：人工标注样本与系统输出逐例对照，记录错因分类准确率、原课证据支持率、补救片段命中率和追问针对性。与“直接把转写交给通用模型回答”基线比较同一批样本，报告失败例和评价规则。即使样本小，也保留原始记录与脚本，不宣称已经证明普遍教学效果。

**性能验证**：在固定客户端网络和服务器设备上处理一小时视频，记录上传、转写、抽帧、OCR、图构建分阶段耗时，峰值内存/显存、服务器临时磁盘峰值和清理结果。抽帧数量与 OCR 数量分别记录，验证粗选确实减少了昂贵处理。

**竞赛材料**：保留源代码和提交记录、运行说明、合法样例、评测脚本、测试记录、开源及第三方资源使用清单。技术报告明确哪些是开源基础能力、哪些是团队自主设计；未实现的候选功能不包装为已完成。官方要求的技术报告、演示视频及成果链接另行制作，本文件不能替代正式提交材料。

## 8. 最近期开发次序

| 阶段 | 交付结果 | 进入下一阶段的条件 |
| --- | --- | --- |
| 1 | Vue 本地播放器 + Java 课程记录 + Python 接口空实现 | 三端能通过契约样例联通 |
| 2 | 短视频转写与时间跳转 | 点击转写定位误差可人工核对 |
| 3 | 人工小规模知识关系 + 错因诊断闭环 | 两种错因演示稳定且引用有效 |
| 4 | 自动知识图与证据校验 | 抽查节点和关系，错误可被发现 |
| 5 | PPT 粗选、OCR、语音融合 | 与纯语音基线比较后决定是否默认开启 |
| 6 | 一小时性能测试和人工标注评测 | 有可复现结果、失败分析和演示素材 |

目前需要团队先确定：用于演示且允许临时上传处理的课程；DeepSeek API 模型 ID、费用预算与服务条款，以及服务器 ASR/OCR 目标设备；人工标注者；上传大小与并发限制、临时文件保留期限。确认后再冻结具体依赖版本和接口 Schema。
