# VideoStudy 项目设计方案（SSD 规格草案）

> 版本：0.1　状态：待团队评审　日期：2026-09-26
>
> 本文是设计规格，不代表系统已经实现或测试通过。以 [需求分析](./需求分析.md) 为上游需求；发生冲突时先修改需求，再更新本设计。
>
> 本文把 SSD 理解为“规格驱动开发”：需求编号 → 设计决策 → 接口与数据契约 → 验收测试 → 证据。它不是比赛官方规定的文档格式。

## 1. 目标与设计边界

产品目标：让学生在观看录播课程后，通过开放式回答暴露具体知识缺口，系统引用课程原文诊断错因，定位最相关的视频片段，随后用针对性追问检查是否理解。**主线是学习诊断闭环，不是单纯生成导图。**

首版选择一门有权使用的课程和有限数量的概念做验证。基础功能是导入、转写、可回放知识图、答题、错因诊断、片段回看、追问、状态记录。视频问答与笔记属于增强功能；逐步 PPT 动画还原及跨课程整合是候选功能，验证后再决定是否交付。

非目标：自动代替教师评分；覆盖所有学科和所有视频格式；保证每个回答都能诊断；训练新基础模型；首版同时提供完整 Web 云服务和离线桌面产品。

## 2. 部署方案决策

**首版设计基线：桌面软件 + 服务器分析。**Electron + Vue 运行在用户电脑上，选择并播放本地原视频；Java、MySQL、Python Agent、FFmpeg、ASR 和 OCR 部署在服务器；Python 调用 DeepSeek API 完成文本推理。首版分析时临时上传完整视频，处理结果入 MySQL，服务器临时视频及中间文件按清理策略删除。点击导图或诊断证据时，Electron 仍播放用户电脑上的原文件。重新打开软件后若原文件已移动，提示用户重新关联。

| 位置 | 组件 | 职责 |
| --- | --- | --- |
| 用户电脑 | Electron + Vue | 选择和播放本地媒体；上传、查看任务进度、导图、转写、诊断与笔记；按时间跳转 |
| 服务器 | Java API + MySQL | 用户和课程、上传会话、任务、证据、答题与学习记录、身份校验 |
| 服务器 | Python Worker + FFmpeg + ASR/OCR | 临时媒体分析、证据检索与 Agent 编排；向 DeepSeek API 发送所需文本 |
| 第三方云端 | DeepSeek API | 知识抽取、错因判断、证据复核与追问的文本推理 |
| 服务器 | 受控临时目录 | 存放上传媒体及中间文件；完成或过期后清理 |

任务用 MySQL 任务表和 Java 调度器控制有限数量的 Python Worker 排队；首版不部署 RabbitMQ。多台分析服务器或大量并发时再评估消息队列。完全本地模型、只上传音频与关键截图属于后续可能的部署优化，不作为首版要求。
## 3. 总体架构与职责

~~~text
Electron + Vue（用户电脑）
  ├─ 本地视频播放器 / 转写 / 导图 / 学习交互
  └─ HTTPS → Java API（服务器）
                ├─ 登录、课程、分片上传、任务与学习记录
                ├─ MySQL：元数据、转写、知识图、证据、诊断
                ├─ MySQL 任务表 → Java 调度器 → 有界 Python Worker
                └─ Python Agent/分析服务 → DeepSeek API（仅所需文本）
                     ├─ FFmpeg、ASR、画面粗选、OCR
                     ├─ 语音与画面对齐、知识图和证据校验
                     └─ 错因诊断、片段检索、追问
                临时文件目录：上传视频、音频与候选截图
~~~

- **Vue/Electron**：原视频由用户选择并在本机播放。客户端通过 HTTPS 上传分析副本；只向服务器发送媒体内容与必要业务请求。客户端保存本地文件关联，服务器不依赖或保存客户机绝对路径。
- **Java**：唯一公开业务 API；负责身份与权限、上传会话、任务状态、MySQL 持久化、Python 结果的结构和引用校验。返回任务 ID 供前端轮询。
- **Python**：通过受控服务器临时文件引用读取媒体并计算；不直接操作用户账户业务数据。FFmpeg、ASR、OCR 在服务器运行；文本推理调用 DeepSeek API。Java 与 Python 通过服务器内部 HTTP 通信；两者部署在同机或通过受控共享存储访问任务文件。
- **临时文件**：分析完成并确认结果持久化后删除；失败、取消、客户端中断的残留文件由定时清理任务按保留期限删除并记录结果。数据库长期保存文字、证据时间和必要缩略信息，不长期保存原视频。
- **回放**：服务器删除分析副本不影响已关联的本地原视频；换设备或本地文件丢失时需要重新选择视频。服务器中的时间戳不会凭空恢复视频文件。
## 4. 需求追踪与验收

| ID | 需求 | 设计实现 | 验收证据 |
| --- | --- | --- | --- |
| R-01 | 导入并回放课程 | 本地文件选择、媒体指纹、播放器 seek | 导入、暂停、跳转和重新关联测试 |
| R-02 | 带时间的课程证据 | TranscriptSegment / VisualEvidence | 抽查时间位置和原文一致性 |
| R-03 | 带出处的知识关系图 | Concept / Relation / EvidenceRef | 节点与关系点击后回到原片段 |

| R-05 | 定向片段与追问 | Evidence retrieval + FollowUp Agent | 同题不同错因得到不同片段和追问 |
| R-06 | 追问后掌握状态 | LearningAttempt 状态机 | 失败、改善、仍不明确三类流程测试 |
| R-07 | 证据核验 | 引用 ID 校验 + 语义支持核验 | 错引与无依据输出检出率 |
| R-08 | 视频问答与错因笔记 | 检索问答、学习记录视图 | 引用可跳转、记录可重现 |
| R-09 | 可运行可复现 | 安装说明、样例与评测脚本 | 新环境复现演示流程 |

每项功能以可运行结果和测试记录验收；文档不把计划等同于完成。

## 5. 核心数据契约

以下是逻辑模型，字段名为接口契约草案。所有时间采用媒体起点后的毫秒整数，区间为 `[startMs, endMs)`，不得混用秒、帧序号或格式化时间字符串。所有 AI 生成对象保留 `provider`、`modelId`、`promptVersion`、`createdAt` 和来源版本，便于重算与审计。

| 实体 | 必要字段 | 约束 |
| --- | --- | --- |
| CourseMedia | id, ownerId, title, sizeBytes, durationMs, fingerprint, status | 服务器不存客户端绝对路径；客户端本地保存 mediaId 到文件的关联，重新选择时核验指纹 |
| TranscriptSegment | id, mediaId, startMs, endMs, text, confidence | 区间合法且不超出媒体时长 |
| VisualEvidence | id, mediaId, frameTimeMs, imageCacheRef, ocrBlocks | OCR 块带文本、位置和置信度；截图非永久必存 |
| Concept | id, mediaId, label, definition, evidenceRefs | 无证据的概念标记为待核验 |
| Relation | id, sourceConceptId, targetConceptId, type, claim, evidenceRefs | 关系陈述需要课程证据，不能仅靠模型常识 |
| EvidenceRef | sourceType, sourceId, startMs, endMs, quote | 引用必须指向现有转写或 OCR 记录；quote 可与原文核对 |
| Exercise | id, conceptIds, prompt, expectedPoints, rubric, evidenceRefs | 题目要能由课程或教师提供的标准核验 |
| LearningAttempt | id, exerciseId, answer, diagnosisId, followUpAnswer, masteryState | 保留前后回答，不覆盖历史 |
| Diagnosis | errorType, explanation, answerSpan, evidenceRefs, remedySegment, followUp, status | status 允许 supported / insufficient / needs_clarification |

初版 `errorType` 采用有限集合：概念记忆错误、概念混淆、因果/推理缺步、条件误用、证据不足无法判定。细分类别由教师标注样本验证后调整，避免无限制让模型自造标签。`masteryState` 可为未评估、待补救、待验证、初步掌握、仍需学习；不能仅因观看了片段就标记“掌握”。

## 6. 关键流程设计

### 6.1 课程导入与分析

1. Electron 选择本地文件，立即可在本地播放器预览。客户端计算大小和可选指纹，向 Java 创建上传会话及课程占位记录；Java 校验身份、配额、允许的格式和声明大小。
2. 客户端经 HTTPS 分片上传完整视频，支持断点续传与取消；Java 将分片合成为仅该任务可访问的临时文件。服务器不得信任客户端传来的任意路径或文件名。
3. 上传完成后 Java 创建 analysisJobId，任务状态为 queued，返回任务 ID。MySQL 任务表记录状态、重试次数和租约/心跳；Java 调度器向受限数量的 Python Worker 派发任务，避免同时加载多个模型挤满显存。
4. Python 从服务器受控路径读取临时视频，FFmpeg 提取音频和候选画面；ASR、OCR、对齐、知识图及证据校验按阶段执行。Vue 在分析时仍可播放用户电脑上的原视频。
5. Java 校验并保存转写、OCR 文字、知识图及时间位置；确认持久化成功后删除服务器临时视频和不必要的中间音频、画面。失败、取消和中断的残留由清理任务按期限处理。
6. 客户端下次打开课程时尝试重新关联本地原文件；不存在时显示导图和文字，但播放前请用户重新选择相同媒体。

任务状态：uploading → queued → extracting → transcribing → sampling → ocr → aligning → graphing → validating → completed；任一阶段可进入 failed 或 cancelled。进度是阶段估计，不伪装成准确剩余时间。
### 6.2 错因诊断与补救

1. 学生提交自由文本回答。Java 读取题目、评价要点、相关概念与课程证据，送给 Python。
2. Agent 先判断回答涉及哪些概念和关系，再给出有限类别中的错因候选；需引用学生回答中的具体字句。
3. 根据错因而非题目标题检索课程证据，优先覆盖该缺口的讲解片段；可结合关键词检索、向量相似度和关系图约束重排。检索实现方式需通过样本测试选择，不预设某模型一定有效。
4. 证据校验检查引用存在、时间合法、片段内容与解释相关。证据不足时标记 `insufficient`，不能虚构“老师在 12:34 说过”。
5. 基于错因与片段生成一道新的情境追问，避免重复原题措辞；学生回答后再次诊断，更新掌握状态。
6. 保存完整过程，生成可编辑的错因笔记。学生可手动纠正转写、诊断或笔记；纠正后相关派生结果标记过期并可重新生成。

“Agent 自主调用工具”仅允许白名单动作，如获取指定时间附近转写、按受限时间范围抽帧、重做局部 OCR、检索证据；每次调用设次数、时间与资源预算，不能直接执行任意命令或访问任意文件。

### 6.3 视频问答与导图回放

导图节点与关系存引用 ID。点击时 Vue 根据 `startMs` 设置播放器当前时间并滚动转写稿；如果引用来自 OCR，显示对应截图时间和识别文字。问答仅基于本课程可检索证据回答；每个关键结论至少关联一个可点击依据。音频文件复用相同时间定位，并高亮转写位置。

## 7. 接口草案

所有响应统一返回 `requestId`，错误返回稳定 `code` 与面向用户的 `message`。Java↔Python 使用服务器内部 HTTP，由 Java 调度器派发任务并保存结果；Python 不直连 MySQL，Vue 不直连 Python。视频通过专门的 HTTPS 分片上传接口传输，不放进任务消息。

| 方法与路径 | 作用 | 关键输入/输出 |
| --- | --- | --- |
| POST /api/uploads | 创建上传会话 | 文件大小、格式、指纹 → uploadId |
| PUT /api/uploads/{id}/parts/{part} | 上传一个视频分片 | 字节流 → 分片确认 |
| POST /api/uploads/{id}/complete | 合并分片并创建课程 | uploadId → mediaId |
| GET /api/media/{id} | 课程元数据与分析状态 | 时长、状态、错误码 |
| POST /api/media/{id}/analysis | 创建分析任务 | analysisJobId |
| GET /api/jobs/{id} | 查询阶段与进度 | status, stage, progress, error |
| GET /api/media/{id}/transcript | 分页读取转写 | TranscriptSegment[] |
| GET /api/media/{id}/graph | 读取知识图与引用 | Concept[], Relation[] |
| POST /api/exercises/{id}/attempts | 提交学生回答 | attemptId, diagnosis, remedySegment |
| POST /api/attempts/{id}/follow-up | 提交追问回答 | newDiagnosis, masteryState |
| POST /api/media/{id}/qa | 提交课程问题并检索依据 | 答案、证据引用、无法回答状态 |

接口冻结前需补充 JSON Schema、版本号、分页、错误码及示例。分析接口必须幂等：同一课程、同一配置的重复请求返回已有运行任务或显式要求重跑。回答提交用唯一请求键避免双击产生重复记录。

## 8. 安全、授权与异常处理

- Python 仅向 DeepSeek API 发送任务所需的转写、OCR 文字、知识关系与学生回答；不默认发送完整视频或所有课程文本。首次使用应说明第三方处理范围并取得必要授权。API Key 只保存在服务器机密配置，记录调用量、失败和重试，避免在日志中写入敏感原文。

- Java 对外提供 HTTPS、用户认证和课程级权限检查；限制上传大小、类型、并发与总临时空间，服务端文件仅存受控目录。Electron 渲染进程不暴露完整文件系统权限。
- 课程、截图、转写和学生答案均按用户数据处理；明确临时文件保留期限，记录删除结果；提供删除课程及其派生结果的入口。
- 不把未授权课程内容上传 GitHub、提交评审公共链接或打包进安装包。公开样例需使用自制或允许再分发的内容。
- 处理媒体损坏、无音轨、OCR 全空、模型缺失、显存不足、任务中断、视频重新关联失败等状态；界面说明可恢复动作。
- 防止将转写或 OCR 中的“请忽略之前指令”等内容当作系统命令。课程文本是待分析数据，不是 Agent 指令。
- AI 生成诊断存在误判，界面提供依据和更正入口；未经核验的结果不包装成确定的教师结论。

## 9. 测试规格与验收门槛

**功能测试**：从导入一个合法视频到两种不同错因的补救闭环；音频-only 输入；节点跳转；媒体文件移动后重新关联；任务取消、失败、重试。

**契约测试**：Java 与 Python 共用 JSON Schema 样例；检查时间单位、引用 ID、空结果、超范围时间、重复请求及版本不兼容。前端使用固定样例数据验证播放器寻址和诊断展示。

**效果测试**：教师标注一门课程的题目、错因和有效讲解区间，记录样本规模、分歧及标注规则。与“直接给通用模型转写稿问答”基线在同一批样本上比较错因分类、证据支持、补救片段命中与追问针对性；公布失败例。追问后表现只作为小规模可行性证据，不声称普遍学习增益。

**性能测试**：在明确设备配置下处理一小时样本，记录总耗时、分阶段耗时、峰值内存/显存、缓存与模型磁盘占用。抽帧与 OCR 数量也需记录，验证粗选预算实际生效。

**参赛完成标准**：可运行核心流程、可复现安装和样例、真实测试数据、清晰的开源资源清单、自主开发边界与 3—5 分钟演示。未完成的 P1/P2 明确标记，不在视频或报告里演示静态伪结果。

## 10. 开发阶段与交付物

1. **规格冻结**：确认部署模式、演示课程授权、题目与错因分类；冻结 R-01～R-06 及接口初稿。
2. **最小纵向闭环**：一段短视频 → 转写 → 手工或半自动知识关系 → 两种学生回答 → 两种不同回看片段 → 追问。先验证诊断主线，再优化自动抽取。
3. **自动课程处理**：接入抽帧、OCR、时间对齐和图谱生成；建立引用校验与失败回退。
4. **效果评测**：固定样本与基线，跑评价脚本，整理失败案例与性能记录。
5. **比赛交付**：完成 README、运行说明、资源清单、技术报告、3—5 分钟演示视频和成果链接。技术报告、视频及答辩 PPT 不出现学校名称、学校 LOGO 或指导教师信息。

每阶段结束更新需求追踪表：需求状态、代码或演示链接、测试结果、已知限制。没有对应证据的需求不能标为完成。

## 11. 待团队确认的决策

- D-01：服务器的 GPU/CPU 配置、并发与上传/临时空间配额，以及临时文件保留期限。
- D-02：演示课程的来源、复制/处理/展示/再分发授权范围。
- D-03：错因标注由谁完成、标注多少回答、如何处理标注者分歧。
- D-04：最终语音、OCR 模型与许可、服务器设备要求；DeepSeek API 模型 ID、费用预算和服务条款。
- D-05：长课程如何先在服务器检索相关片段再调用 DeepSeek；是否需要向量索引，须以小样本检索效果决定。
- D-06：P2 的 PPT 步骤还原是否进入参赛版本。
