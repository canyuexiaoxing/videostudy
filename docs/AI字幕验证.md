# 中英 AI 字幕验证记录

验证日期：2026-10-03。使用本机 Java 21、Python GPU 容器、MySQL 和 Vue 页面，以及已配置的 DeepSeek API。所有字幕都保留 Whisper 原始 ID、顺序和时间；原始转写及导图依据不覆盖。

## 功能与保护规则

- 原文/AI 字幕切换，目标语言为原语言、中文、英文；新分析默认自动生成，高级选项可关闭。
- 同语言按近音和上下文校准，限制实际增删，拒绝多余填充词、伪造 OCR 引用和明显不近音改写。标点不消耗正文增删预算。
- 通过规则的候选修改集中做一次语义复核，只认可或舍弃已有候选。复核失败保留原文，最多三次请求尝试。翻译不受近音约束。
- 同页分组后异步提供语音和 OCR；字幕任务与页面理解/导图并行。字幕失败不修改主分析状态。
- 已有课程只用保存的文字资料生成；删除课程级联删除来源和字幕，晚到结果不能恢复被删除记录。

## 自动化验证

Java 回归测试 38 项通过，包括实际上传接入、字幕 HTTP 请求序列化、私有回调验证、任务幂等、失败重试、服务恢复、删除竞争和时间/引用校验。前端 16 项通过，构建通过，覆盖原文回退、切换时间保持、课程切换后的旧响应隔离和轮询有限自动重试。

最终 Python GPU 容器 125 项测试全部通过，包含媒体集成与字幕模块。另显式运行三个历史 Python API 合约函数，避免把未被 unittest 发现的普通测试函数当成已执行。

真实模型 API 的四种小样均通过：`我王祺吃饭了 → 我忘记吃饭了`、`Their is a cat on the table. → There is a cat on the table.`、中文到英文、英文到中文。模型没有收到原音或图片，小样由人为构造，不构成真实课程纠错准确率评测。

## 准确性与成本边界

首轮检查发现近音过滤仍会接受无意义新词，故增加候选语义复核；发现“主体/主题”这类同音概念也需检查引用原文，最终规则进一步保守。被规则接受仅表示满足当前检查，不表示已经核实老师实际说法。

仍有大量原始错字保留。校准不听原音，无法确认漏字、数字读音或原始片段边界；OCR 本身也会出错。需提供独立参考字幕才能测量字错误率、误改率及改进幅度，不能用“改了多少处”或模型自报理由证明准确率。额外 API 请求增加费用，并行不保证所有服务器的总时间完全不变。本次时间包含模型服务波动及少量验证请求，不作为容量承诺。

抽查 v3 仍发现可疑调整，例如“一支的 → 一值的”；模型语义复核不是正确性证明。该功能作为可切换的校准参考交付，原文为默认版本，学习诊断与导图仍使用原始证据。本次未完成有原音参考的误改率评测。
