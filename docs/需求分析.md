# 视频学习错因诊断系统：需求分析（草案）

> 本文件是待验证的需求草案，不代表功能已经实现或效果已经验证。拟申报方向：2026 AIC「AI+开源」主题赛的“开源赋能的 AI 应用创新”。

## 一、问题与目标

学生看完课程视频后，往往知道自己答错，却不知道具体混淆了哪个概念、缺少哪一步推理，也难以从长视频中找到针对性的讲解。转写、导图和普通问答可以整理课程，却不能自动证明学生的知识缺口得到纠正。

本作品聚焦：**根据学生的解释或答案，识别具体错因，找到原课中最相关的讲解片段，生成针对性追问，并检验理解是否改善。**

首版选择一门有权使用的课程和有限数量的知识点，不声称覆盖所有学科或替代教师评价。

## 二、用户与场景

- **学生**：希望知道错在哪里、该回看哪段、回看后是否真正理解。
- **教师或助教**：提供题目、常见错因和对应讲解片段，核验系统输出。

例如学生说“训练集准确率低就是过拟合”。系统应识别其混淆训练表现与测试表现，指出学生回答中的依据，链接教师解释两者差异的片段，再换一个例子追问。若另一名学生能区分两种表现，却不理解模型复杂度为何导致过拟合，应收到不同的片段与追问。

现有项目 [CoursePilot](https://github.com/wansui976/CoursePilot/blob/main/README_en.md) 已有转写、PPT OCR、导图、练习、时间戳问答和薄弱知识点分析。因此，这些基础功能的组合不能作为主要创新点。真实需求证据仍须通过学习案例或访谈补充，不预填虚构的用户数据。

## 三、功能需求与优先级

| 优先级 | 需求 | 验收依据 |
| --- | --- | --- |
| P0 | 导入有权使用的视频或录音，播放并展示带时间的转写稿 | 可播放、暂停、按时间跳转 |
| P0 | 提取课程概念及其关系，记录原句、来源和时间段 | 点击节点或关系可查看对应原课依据 |
| P0 | 接收开放式回答，诊断具体错因 | 输出错因、触发判断的学生表述；与人工标注对照 |
| P0 | 根据错因推荐并播放原课片段 | 不同错因能定位不同讲解；人工核对片段相关性 |
| P0 | 给出针对性追问并更新掌握状态 | 保存原回答、追问、新回答和状态变化 |
| P1 | 核验知识关系及诊断的证据 | 无充分依据时不输出确定性断言；人工抽查支持率 |
| P1 | 保存个人错因笔记、提供带可点击依据的视频问答 | 能追溯一次完整补救过程 |
| P2 | 逐步还原 PPT 动画内容与讲解步骤 | 用选定样本验证后决定是否纳入 |
| P2 | 跨课程知识整合 | 不作为首版必备 |

首版重点打通“课程证据 → 学生回答 → 错因诊断 → 定向回看 → 追问验证”。普通导图、笔记和问答为这条主线服务。

## 四、Agent 输入、输出与行为边界

**输入**：带起止时间的语音转写；可选的 PPT 截图时间与 OCR 文字；带证据的概念关系；题目、学生回答和学习记录。OCR 文字不能等同于对整张图表或公式的完整理解。

**每次诊断至少保存**：目标知识点、学生回答、错因及解释、用于判断的学生原话、课程依据与时间段、推荐片段、追问、新回答和后续判断。用户应能查看这些依据。

音频讲解是主要课程依据，PPT OCR 补充未口述的文字。两者冲突时保留来源并核验。回答不足以判断时先澄清；找不到课程依据时明确说明，不凭空贴错因标签。

```text
课程视频/录音 → 转写与按需 PPT OCR → 带出处的知识关系
→ 学生解释或答题 → 诊断错因 → 回看原课片段
→ 针对性追问 → 更新掌握状态和个人错因笔记
```

## 五、非功能需求

- **可追溯**：核心结论可追到学生回答和课程时间段；有时间戳不等于证据成立。
- **可用性**：点击证据即可跳转播放器，并展示推荐理由。
- **性能**：一小时视频采用异步分析并显示状态；耗时、峰值内存和磁盘占用以实测为准。
- **存储与上传**：桌面软件保留并播放用户本地原视频；首版经 HTTPS 临时上传完整视频供服务器分析。分析结果保存后删除服务器临时视频和中间文件；失败或取消的残留按期限清理。再次回放仍需用户设备上的原文件，移动或删除后应提示重新关联。
- **隐私与权利**：只使用获授权的课程样本；转写/OCR 文字及学生回答在必要范围内发送给 DeepSeek API，须明确告知并取得必要授权。API Key 仅保存在服务器，不在仓库公开无权再分发的视频、个人信息或密钥。
- **可靠性**：检查转写错误、OCR 错字、错误引用及用户内容中的提示注入；保留失败案例。
- **可复现**：提供运行说明、合法样例或脱敏说明、评测方法与脚本。

## 六、AI 与开源资源、自研边界

拟评估 Whisper/whisper.cpp 转写、FFmpeg 音视频处理、PaddleOCR 或替代方案识别 PPT 文字，以及 DeepSeek API 进行知识抽取、错因诊断、证据复核和追问；课程片段检索由服务器程序先完成。**具体版本、来源和许可证尚未确定；首版部署方式为桌面客户端 + 服务器分析，正式材料须据实填写。**

团队拟自主设计带出处的知识关系、错因分类与诊断流程、按错因选择补救片段的策略、追问与状态更新、界面交互、测试样本和评测脚本。若复用其他项目代码，须记录上游来源、许可与修改边界。正式提交需附《开源及第三方资源使用清单》，并提供至少一种有权开放、可复用或可验证的成果。

## 七、验证计划

选用有权使用的一门课程，由教师或熟悉课程者预先标注少量题目、常见错因、判断要点和相关讲解片段。准备正确、不同错因、模糊和超出课程范围的回答，记录样本规模、标注方法与分歧。与“转写稿 + 通用模型直接答题”或“普通导图 + 自动出题”基线比较，使用相同样本和标准。

| 指标 | 测法 |
| --- | --- |
| 错因分类准确率 | 与人工标注逐例比较，展示混淆案例 |
| 证据支持率 | 人工核对知识关系和诊断是否被引用片段支持 |
| 补救片段命中率 | 人工检查片段是否解释对应错因，记录定位偏差 |
| 追问针对性 | 比较不同错因的追问是否针对不同知识缺口 |
| 补救后理解变化 | 比较原回答与新情境追问；披露未改善案例 |
| 处理成本 | 测量一小时样本的耗时、峰值内存和磁盘占用 |

演示应展示同一道题的两种错因及不同的回看片段和追问。小样本结果不夸大为已证明教学效果。
