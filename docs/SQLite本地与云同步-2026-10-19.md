# 本地 SQLite 与模拟云端 MySQL（2026-10-19）

## 已实施

当前开发分支为 `feature/local-sqlite`。本地后端默认使用 SQLite，云端进程使用 MySQL。桌面 0.2.0 顶部增加“云同步”，只有主动连接、上传或下载才请求云端。启动本地后端和打开同步窗口不会自动连接云端。

- 本地 API：`http://127.0.0.1:18080`，SQLite 文件位于项目 `.local/database/framewise.db`；Docker 映射到 `/data/database/framewise.db`。
- 模拟云端 API：`http://127.0.0.1:18081`，进程角色 `FRAMEWISE_ROLE=cloud`，使用原 Docker MySQL 数据卷 `videostudy_mysql-data`。
- MySQL 端口没有公开给桌面端。数据库凭证留在云端容器，客户端通过 HTTP 同步接口交换数据。
- SQLite 采用 WAL、外键、10 秒忙等待与 IMMEDIATE 事务；兼容重复请求错误和原字幕加锁逻辑。独立 Flyway 迁移目录，保留原 MySQL 迁移。
- 同步按单节课程保存版本化快照。上传支持重复请求幂等；检测版本冲突；下载不会覆盖本地未上传的修改。接收数据经过固定表/字段、关联关系和内容哈希校验，导入在事务中完成。
- 云端进程没有扫描或启动本地分析控制器与调度任务，不调用语音/OCR/YOLO或大模型。
- 现有 MySQL 课程表未清空。部署前备份；旧历史若存在可通过云端读取并导入 SQLite。本次迁移前历史数量为 0，没有需要导入的旧课程。

## 当前同步范围与边界

同步后端数据库中的课程信息、字幕、导图、AI 解读、章节、练习/作答、题目答疑和课程对话。上传中不带原视频、媒体路径、模型文件、API Key、回调凭证和运行锁。

截图和其他文件尚未同步；随手笔记、标注图片和预览仍沿用本机 IndexedDB 存储，尚未迁入 SQLite。因此跨设备下载课程后，文字结果可用，缺少的课件图片不会自动出现。原视频需重新选择并核对指纹。

此实现为私有单用户的模拟云端，`SYNC_TOKEN` 是开发配对凭证，不是账号系统。没有实现邮箱登录、多用户归属隔离、自动同步、删除传播或图片同步，不应作为公开多用户服务直接发布。

桌面 EXE 仍依赖本机后台与 Python/模型运行环境；SQLite 迁移不等于已完成后台独立安装器。本次本地后台仍在 Docker 运行，但数据库本身已是用户磁盘上的 SQLite 文件，不再依赖 MySQL。

## 配置和启动

- `SPRING_PROFILES_ACTIVE=sqlite`（默认）：本地。
- `SQLITE_PATH`：可指定 SQLite 文件路径。
- `SPRING_PROFILES_ACTIVE=mysql` 且 `FRAMEWISE_ROLE=cloud`：模拟云端；沿用 `MYSQL_JDBC_URL`、`MYSQL_USER`、`MYSQL_PASSWORD`。
- `SYNC_SERVER_URL`：本地后端访问云端地址；当前容器内是 `http://cloud-api:18080`。
- `SYNC_TOKEN`：至少 32 字符的随机配对凭证，两端一致，已写入未跟踪的 `.env`。不要发给聊天或提交 Git。
- `SYNC_OWNER`：当前私有空间标识，默认 `private`。

`compose.yaml` 已包含 mysql、agent-python、本地 java-api 和 cloud-api；GPU/YOLO 的原有叠加配置保持使用。可以只启动本地服务，云端停机不影响 SQLite 数据读写。

安全重部署脚本：`scripts/dev/deploy/sqlite-cloud.py --docker <Docker CLI 路径>`，会先拒绝活跃任务、保存 MySQL 备份、构建新后端镜像并核实连接。它不删除数据卷、不执行课程重分析。

SQLite 使用 WAL 时请用 SQLite backup API 备份，不要只复制正在使用的单个 db 文件。
