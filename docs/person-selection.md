# YOLO 人物遮挡过滤

该功能接在“粗选采样 → 画面变化判断”之间。以固定机位、固定黑板为第一版范围；人物掩膜只用于决定截图时间，原始截图和 OCR 输入不被人物掩膜涂黑。

## 开关与安装

视频工作台左侧选择 **人物过滤**，在独立板块开启“排除人物动作”。默认关闭；设置按本地视频指纹保存，开始新分析时作为 `personSelectionMode=off/adjacent` 快照提交。开启使用 GPU 相邻帧共同可见区域规则，无需手动人物框；原图及 OCR 输入不涂黑，覆盖检查和补录照常执行。工作台改设置不影响进行中的任务；失败重试读取数据库中原任务的设置。

部署环境仍可设置 `PERSON_SEGMENTATION=off/auto/cpu/cuda`。仅未指定逐任务参数的旧调用沿用该配置和原历史清晰画面算法；新前端会明确提交 off 或 adjacent，因此界面关闭会覆盖服务环境中的启用值。adjacent 强制 CUDA，不转为CPU；GPU或模型不可用时回退普通粗选，并记录安全失败原因。运行库与模型仍需要按下述方式安装。

在 `.local/models/yolo26/yolo26n-seg.pt` 放入官方 v8.4.0 权重。来源：[Ultralytics assets](https://github.com/ultralytics/assets/releases/download/v8.4.0/yolo26n-seg.pt)，SHA256 为 `361fbfabab285c3237700b6bb91d7ecfa602cd945fffda8dbe1242829b71e73f`。程序校验后才加载，不自动下载任何权重。

可复现安装：

```powershell
docker compose -f compose.yaml -f compose.gpu.yaml -f compose.person.yaml build agent-python
docker compose -f compose.yaml -f compose.gpu.yaml -f compose.person.yaml up -d agent-python
```

只用 CPU 时省略 `-f compose.gpu.yaml`。Torch/Ultralytics 安装在 `/opt/person` 独立解释器内；OCR 原环境不改动，人物模型使用独立子进程，避免 Paddle 与 Torch 的依赖版本相互覆盖。关闭时仅使用 `compose.yaml`（或把 PERSON_SEGMENTATION 配成 off）。

本机已有测试运行库，可复用项目内 `.local/dev/yolo-runtime/venv`：

```powershell
agent-python/.venv/Scripts/python.exe scripts/dev/deploy/person-selection.py --mode auto
```

`--mode off` 关闭。该脚本先检查没有队列任务再更新 Python 服务，不分析历史课程、不调用收费模型。此本机快捷配置保存到 `.local/dev/person-compose.yaml`；后续 grouped-course.py 部署会保留它。其他机器应使用上面的标准构建，不能直接复制本机 Linux 虚拟环境。

## 比较与异常

工作台“人物过滤”使用相邻帧规则：

- 只比较前后两帧均可见且不属于人物的有效区域，超过用户设置的变化比例才保留当前截图。
- 保留首尾帧；不使用历史清晰记录、重新露出补留和30秒累计保留，没有共同可见区域时不作变化判断。
- 此规则旨在减少人物动作造成的OCR候选，尚未证明关键板书无遗漏；覆盖检查与补录是后续独立步骤，不能保证补齐所有被跳过内容。
- `personSelectionMode` 通过Java数据库和Python工作进程绑定逐任务传递，不修改服务全局环境。模式和策略版本进入视觉缓存键；每次绑定重置参数，避免跨任务污染。

仅部署模式、未传逐任务参数时，保留原历史清晰记录算法：

- 每个视频独立保存可见性比较状态；只在人物进程里跨任务复用模型，不共享课程内容。
- 已观察过的可见位置与上次保留的清晰内容比较；被遮挡部分不参与判断。最初未见过的部分露出后保守保留，不假定内容不变。
- 内容变化或新区域露出时保留真实截图；缓慢书写累计比较，达到间隔后检查小变化。大量遮挡时最长30秒保守留一张。擦除、修改作为变化处理，不拼接不同时刻的黑板。
- 只识别/忽略区域与其时间节点继续有效。人物边缘有一个小的安全余量；手指、孤立的手、模糊轮廓仍可能漏检。
- 模型不可用、超时或推理错误时，恢复普通画面粗选，并记录阶段、失败类型、抽帧数和候选数；失败的子进程淘汰。取消或父进程退出后释放模型进程。
- 模式、模型版本与运行库变化进入视觉粗选缓存键；关闭时保持原缓存身份。不会自动更新历史结果。

模型首次加载会有冷启动；后续视频复用常驻进程，仍持续占用相应内存/显存。模型减少的 OCR 时间是否抵过新增开销，需要真实黑板走动视频和转写/OCR并发验证；不能由单图推理速度推断。
